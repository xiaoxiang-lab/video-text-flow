## 1. 输入契约

标准 SRT：序号、`时:分:秒,毫秒 --> 时:分:秒,毫秒`、一到多行文字、空行分隔。

解析出每条：`index / start / end / raw_text / clean_text`。

### 解析前清洗

第 8 节管的是**语义层**异常。这一节管**文件层**——中文 SRT 在 Windows 上最常炸的就是这些。

| 情况 | 处理 |
|---|---|
| **编码** | 按 UTF-8 → UTF-8-BOM → GBK/GB18030 → UTF-16LE 依次试；读出来大量 `` 或 `?` 就换下一个。剪映、Arctime 导出的中文 SRT 常是 GBK。定下来的编码写进 `state.json` 的 `srt_encoding`，续跑用同一个 |
| BOM | 剥掉，否则第一条序号变成 `﻿1` |
| 时间码变体 | `00:00:01.000`（点号）、`0:00:01,00`（缺位）、`00:00:01,0` 一律归一化为 `时:分:秒,毫秒` |
| 样式标签 | `<i>` `<b>` `<u>` `<font …>` `{\an8}` 去掉 |
| 非台词标注 | `[音乐]` `[掌声]` `（笑）` 去掉 |
| 说话人前缀 | 行首的 `- ` 或 `张三：` 去掉 |
| WebVTT 混入 | 以 `WEBVTT` 开头，可能带 cue id 与 `NOTE` 块，一并剥离后按 SRT 处理 |
| 空文本条目 | 只有时间码没文字 → 不单独成条，那段时间并入前一镜的静默 |
| 相邻重复文本 | 自动字幕常见 → 合并为一条，不重复计入语义 |
| CRLF / 末尾无空行 | 归一化，不算异常 |

### raw_text 与 clean_text 是两份，不能只留一份

```
raw_text    原样保留     → 参考图提示词里「本镜旁白原文，逐字照抄 SRT」用它
clean_text  清洗后       → 计字块、语义切分、上屏文字用它
```

参考图提示词模板要求逐字照抄 SRT。如果清洗掉了 `<i>` 却没留原文，
「照抄」的就不是原文了——这个坑不写明一定会踩。

**时间归属规则**：镜头必须无缝覆盖整条时间轴，不留空洞、不重叠。

```
第 N 镜自然时长 = 第 N+1 镜首条字幕的 start − 第 N 镜首条字幕的 start
最后一镜自然时长 = 最后一条字幕的 end − 该镜首条字幕的 start + 0.8 秒收尾
```

字幕之间的静默间隙归属于它前面的那个镜头，因为那段时间画面仍要有内容。
**这条没有例外**——再长的静默也不单独成镜，理由见第 8 节。

## 2. 镜头两型

分镜前先给每一镜定型。两型的处理路径完全不同，混用会出错。

| | 解释型 | 展示型 |
|---|---|---|
| 画面主体 | 有主体、有动作、有因果 | 一块需要观众逐字读完的静态内容 |
| 判据 | 旁白在**解释**某个东西 | 旁白在**朗读**这块内容本身 |
| 典型 | 机制、步骤、对比、结论 | 引文、清单、代码、表格、截图、对照 |
| 生成时长 | 就近吸附到 4/6/8/10 | 取最接近自然时长的一档，超 10 秒取 10 |
| 超 11 秒 | 拆分 + 桥接帧 | **不拆分**，靠末帧定格补足 |
| 差值 | 正走收束，负走定格补差 | 同左，但负差值通常更大 |

**两型的生成时长都用同一张就近吸附表（第 5 节）**，区别只在超限：
解释型超 11 秒要拆，展示型不拆、封顶 10 秒。

### 展示型镜头的处理

```
1. 生成时长 = 4/6/8/10 里最接近自然时长的一档；自然时长 > 10 秒一律取 10；
2. 内容固定是「文字块入场 → 带字载体定格」，不做超限拆分；尾部按第 6 节的尾部契约表选档；
3. 生成短于旁白 → 剪辑里用最后一帧定格补足；生成长于旁白 → 尾部裁掉；
4. 分镜表 `生成时长` 列填 `展示 N.Ns → 生成 Ms`；
5. `差值` 列记 `补差 X.Xs` 或 `余量 X.Xs`。
```

**理由**：取最接近的档，多数展示镜能原速播完，观众不会盯着一张静止画面读四秒字。
只有超 10 秒的长引文才需要定格延长——那是平台上限，不是编排选择。
展示型仍然不做超限拆分：把一段引文劈成两条片子，观众会在接缝处丢读。
入场后带字载体定格是为了让观众读字，但**画面不要求全程完全冻死**——余量够大时
加一次收束动作，既填住尾部、又避免画面僵硬，阈值查第 6 节的尾部契约表。

**例外**：展示型镜头满足下面**任一条**时，按内容的自然段落分成两个展示镜，
每镜展示一部分，用同一版式做转场锚点。这是内容分段，不是时长拆分：

```
a. 自然时长 > 15 秒                    ← 定格太久，观众读完了还在等
b. 上屏文字拆满 8 张卡仍装不下         ← 版面装不下，见下面「展示型的内容完整性」
```

两条触发条件独立，命中一条就分。分完之后每个展示镜各自再按上面的流程取档。
第 8 节「单条字幕 > 11 秒」那条只管**单镜封顶 10 秒**，不覆盖本例外——
一条 18 秒的展示型字幕先按本例外分成两镜，再各自取档。

### 展示型的内容完整性

**展示型镜头的上屏文字必须完整覆盖本镜旁白，一个字都不许压缩或删减。**

这是展示型的定义决定的：它之所以是展示型，就是因为观众要逐字读完这块内容。
砍掉一半再让观众读，这一镜就两头不靠了——既没有解释型的动作，
又没有展示型的完整内容。

风险出在**文字必须在参考图里生成**、不走 `post only` 的项目上。
`generated` 有 2–14 字块的安全区，一行旁白超过 14 字块时会诱使你砍字。

```
超 14 字块 → 拆成多张短句卡   ✅
超 14 字块 → 删字压缩         ❌
```

拆卡的落点选在语义断点上（主语与谓语之间、条件与结果之间），不要为了凑字数硬切。
**展示型单镜可放 8 张卡，与文字密度档无关**（密度档只管解释型，见第 11 节校验器 9a/9b）。
绝大多数长句拆两张就够，不必因为「怕挤」提前砍字——
**先拆满 8 个名额，仍装不下才走上面的例外分成两镜**。

计字口径的正典是 [prompt-keywords.md](prompt-keywords.md)「计字口径」一节，本节不复述。
按字母数而不是按字块计，会把本来装得下的句子误判成超限，然后砍掉不该砍的字。

拆卡会让单镜载体数上升，逐个载体写明形状差异，避免做成同一种形状。
拆到 6–8 张时按语义分 2–3 组、每组一种载体形状——八张卡最容易做成八个一模一样的牌子。

### 展示型镜头的视频提示词

以入场为主，不写持续大幅运动。**模板正典在
[prompt-templates.md](prompt-templates.md) 第 5 节末尾**，本节不重复文本。

要点：**入场时间 = min(生成时长 ÷ 3, 2.0 秒)**，入场结束**带字载体**定格；
尾部（含要不要加收束动作、末段留多久）全部按第 6 节的尾部契约表选档。

**定格的是带字载体，不是整个画面。** 无字部件能否进出画面、运镜动不动，
按 [prompt-templates.md](prompt-templates.md) 第 5 节的**动感预算三档**取档，
本节不复述档位。分批入场不改变上面的入场时间公式，批次在同一个窗口内均分。

**为什么封顶 2.0 秒**：展示型的目的是让观众逐字读完，入场越短、留给读的时间越长。
纯三分之一在长档上反效果——10 秒档要等 3.3 秒才能开始读。
4 秒档取 1.3 秒、6 秒档取 2.0 秒不受影响，8 / 10 秒档一律封在 2.0 秒。

## 3. 三级优先级

```
1. 语义完整（一镜一个知识点、多个部件分时入场完成该知识点）  ← 硬约束，任何情况不可让步
2. 时长贴靶（4/6/8/10 秒）                  ← 软优化，只在语义允许的切点里择优
3. 差值最小                                  ← 最低，可牺牲
```

顺序不可颠倒。为了凑时长而把两个知识点塞进一镜，是本 skill 最严重的错误。
一镜内的多部件动作（如主体落下 → 辅助卡滑入 → 标题锁定）服务于同一个知识点，
是一个连续动作流，不构成第二个知识点。

展示型镜头只受第 1 条约束，不参与第 2、3 条的切点择优——
它的边界由引文本身的起止决定。但它的**生成时长同样按第 5 节就近取档**。

## 4. 分镜算法

```
第一步 · 找候选切点
  逐条读字幕，在下列位置标记候选切点：
    - 话题转换、因果转折、举例开始或结束；
    - 从「是什么」转向「怎么做」或「为什么」；
    - 主体对象发生更换；
    - 引文、清单、代码块的开始与结束；
    - 字幕之间静默 ≥ 0.8 秒。
  候选切点只表示「这里可以切」，不表示「这里必须切」。

第二步 · 语义成镜并定型
  从第一条字幕出发，向后合并，直到再合并就会引入第二个知识点为止。在最近的候选切点断开。
  给每一镜标注解释型或展示型。这一步只看语义，不看时长。
  注意：一镜内允许多个部件分时入场（构成一个连续动作流），不算第二个知识点；
  判定合并边界的唯一标准是「是否引入新的语义单元」，不是部件数或动作数。

第三步 · 贴靶微调（仅解释型）
  计算本镜自然时长，查第 5 节吸附表得到生成时长与差值。
  自然时长 ≥ 3 秒时差值必然 ≤ 1.0 秒，不需要微调，直接转第四步。
  只有自然时长 < 3 秒（差值必然 > 1.0）才在语义允许的相邻候选切点里找更好的落点：
    - 向后挪一个切点（多并一条字幕）→ 检查是否引入第二个知识点或主动作；
    - 向前挪一个切点（少并一条字幕）→ 检查本镜是否还讲得完整。
    两个方向都不允许时，保持原样，标注 `短镜`，转第五步。

第四步 · 超限拆分（仅解释型）
  自然时长 > 11 秒 → 按第 7 节拆分。
  10–11 秒之间不拆，按第 5 节取 10 秒生成，差值走补差。
  展示型镜头跳过本步。

第五步 · 差值归置
  差值为正（生成长于旁白）→ 按第 6 节写尾部定格或收束动作。
  差值为负（生成短于旁白）→ 记「补差」，要求末帧绝对稳定，剪辑里定格延长。

第六步 · 校验
  跑第 11 节的校验器。任何一项不通过，回到第二步重切，不要打补丁。
```

## 5. 吸附表

两型通用。**就近**吸附，不是向上——分界点落在 5 / 7 / 9。

| 自然时长 | 生成时长 | 差值 = 生成 − 自然 |
|---|---:|---|
| (0, 3) | 4 | > +1.0，最多 +3.2，必为 `短镜` |
| [3, 5] | 4 | −1.0 ~ +1.0 |
| (5, 7] | 6 | −1.0 ~ +1.0 |
| (7, 9] | 8 | −1.0 ~ +1.0 |
| (9, 11] | 10 | −1.0 ~ +1.0 |
| > 11 | 解释型拆分（第 7 节）；展示型取 10 | 展示型补差可超 1.0 |

**为什么是就近而不是向上**：平台只能生成 4/6/8/10，向上吸附会让 4.9 秒的旁白配 6 秒的片子，
白多出 1.1 秒还得写收束动作；就近吸附配 4 秒，只差 0.9 秒，剪辑里末帧定格补一下看不出来。
展示型受益更大——旧规则下 7.6 秒的引文只生成 4 秒，观众要盯着静止画面读 3.6 秒。

**由此得到一条硬规律，可直接进校验器**：

```
自然时长 ≥ 3 秒  ⟹  |差值| ≤ 1.0 秒
```

3 秒以下之所以例外，是因为平台没有 2 秒档，4 秒是地板。

**边界取 ≥ 3，短镜取 < 3，两者严格互补，不留缝也不重叠。**
自然时长恰为 3.0 秒时余量正好 1.0，属正常镜、不必写收束动作——
若把短镜定义写成 ≤ 3.0，它就会同时被「必须写收束」和「余量未超 1.0 无需写」两条命中。
**阈值和不等号方向必须成对改，改一个不改另一个就会复发这个矛盾。**

**差值的两个方向**：

| 差值 | 含义 | 处理 |
|---|---|---|
| 正（生成 > 自然） | **余量**，片子比旁白长 | 尾部定格或收束动作，见第 6 节 |
| 负（生成 < 自然） | **补差**，片子比旁白短 | 末帧必须绝对稳定，剪辑里定格延长 |
| 0 | 正好 | 直接用 |

补差在 1 秒以内几乎不可察觉，不必为了消掉它去改切点。

### 短镜

自然时长 **< 3.0 秒**的镜头，生成 4 秒必然余量 > 1.0，且一个知识点通常撑不满。
优先尝试与相邻镜合并；语义不允许时保留，并在分镜表标注 `短镜`。

**`短镜` 是校验器第 5 条的两个例外之一**（另一个是展示型自然时长 > 11 秒）：
它的余量可以超过 1.0，**最多 3.2**——第 8 节规定单条字幕 < 0.8 秒一律并入相邻镜，
所以单独成镜的自然时长下限是 0.8 秒，余量上限就是 4 − 0.8。
这类镜的尾部按第 6 节的尾部契约表选档，余量越大要写的东西越多，
绝不能留一段没规定的静止——模型会在里面自行发挥。
合并只在语义允许时做——为了压余量而把两个知识点塞进一镜，违反第 3 节的硬约束。

## 6. 差值处理

**差值的本质是生成时长与旁白时长的偏差，不是播放时长。**

平台只能生成 4/6/8/10 秒，就近取档后片子可能比旁白长一点，也可能短一点。
两种都在剪辑里一步解决，音画不会累积漂移。

因此视频提示词要这样编排：

- 时间码一律按**生成时长**写，因为模型生成的就是那个长度；
- **关键动作必须在尾段之前完成**，截止时刻按下表算；
- 剩下的部分是尾部安全带（余量）或末帧定格素材（补差）。

**余量在剪辑里一律裁掉，裁到旁白的呼吸点，不要留成整数秒。**
4/6/8/10 是平台的生成限制，不是成片的节奏。整片十几镜如果都原样留着整数时长，
镜头长度会排成一条等差网格，听感上很机械——实拍参考片里量出来的镜头长度
是 4.0/4.27/4.33/4.86/5.53/6.13/6.57/7.2 这样的杂数，正是因为每一镜都裁到了旁白落点。

裁的落点选在**旁白句子结束后的自然停顿处**，不是某个整数刻度。
余量不足以裁到停顿点时，宁可留两三帧与下一镜重叠，也不要为了凑整数而多留半秒空转。

**这条只管剪辑成片的长度，不改变视频提示词要写的内容。** 生成阶段仍要按尾部契约表
把整个生成时长填满——余量段该写的收束动作、静止指令一条不能省，否则模型会在
没有指令的静止段里自行发挥。裁剪发生在生成完成之后，两件事在流水线的不同环节。

**两条例外：**

- **补差镜**没有余量可裁，靠末帧定格补足；
- **拆分镜的上游片段不适用本条。** 它的末段绝对静止是下游片段第 0 帧的抽帧来源，
  必须完整保留到生成时长末尾。按呼吸点裁掉它，片段 a 成片的最后一帧就不再等于
  片段 b 的第一帧，桥接处会出现可见接缝——这一段是素材，不是余量。

### 尾部契约表

**这是尾段时长与关键动作截止的唯一正典**，其余文件引用本表、不重复数字。

**先按差值选一个基础档，再看有没有覆盖行叠加。** 两组分开，不会同时命中两个基础档。

**基础档**（按该镜差值四选一，解释型与展示型通用）：

| 基础档 | 末段绝对静止 | 之前允许什么 | 关键动作前需留 |
|---|---:|---|---:|
| 余量 ≤ 1.0s | 0.2s | — | 0.2s |
| 1.0s < 余量 ≤ 2.0s | 0.6s | 一次**收束动作** | 1.0s |
| 余量 > 2.0s（只出现在短镜） | 0.6s | 显式静止 `余量 − 1.0` 秒，再一次**收束动作** | 余量 |
| 补差 ≤ 0.5s | 0.2s | — | 0.2s |
| 补差 > 0.5s | 0.2s | 一次**微动填充** | 0.4s |

**覆盖行**（命中就改写基础档的对应值，可叠加）：

| 覆盖行 | 改成什么 |
|---|---|
| 展示型 | 时间线由入场时间决定，**关键动作截止公式不适用**；入场结束即定格，末段绝对静止取 0.2s；余量落在第二档及以上时可加一次收束动作 |
| 拆分镜的上游片段（末帧要被抽出来当下游首帧） | 末段绝对静止**一律 0.6s**，需留同步抬到 **0.6s 加上该基础档里动作占用的时间**（基础档一、四为 0.6；档二为 1.0；**档三不变，仍为余量**——它的需留本来就大于 1.0，
「抬到」对它无效；档五为 0.8） |

```
关键动作截止 = min(自然时长, 生成时长 − 该档「关键动作前需留」)      ← 展示型不适用
```

**「需留」的定义式**：

```
需留 = 末段绝对静止 + 收束动作或微动填充占用的时间 + 显式静止段（只有余量 > 2.0 档有）
```

按这个式子逐档验算：档一 0.2 + 0 = 0.2；档二 0.6 + 0.4 = 1.0；
档三 0.6 + 0.4 + (余量 − 1.0) = 余量；档四 0.2 + 0 = 0.2；档五 0.2 + 0.2 = 0.4。全部对得上。

**两个动作时长常数**（需留列的算式全靠它们，写在这里以免无处可查）：

```
收束动作   ≈ 0.4 秒
微动填充   ≈ 0.2 秒
```

从 [prompt-motion.md](prompt-motion.md) 第 3 节挑动作时，挑耗时明显超过这个数的
（例如一个缓慢的两段式沉降），需留要相应加大，否则会挤掉主动作。

一条兜底：**任何片子的末段绝对静止 ≥ 0.2 秒**。
档一的需留因此是 0.2 而不是 0——余量本来就不足 0.2 的镜（例如自然 6.0 秒配生成 6 秒），
关键动作要提前到 5.8 秒落定，把这 0.2 秒让出来。

「绝对静止」指无位移、无呼吸亮度、无运镜、无材质响应。

**硬约束：档位名与数值只允许出现在上面这张表里。** 其余任何地方一律写
「按尾部契约表选档」，不得就地列举「余量 ≤1.0 / 余量 >1.0 / 补差 ≤0.5……」——
这套列举被复制到哪里，哪里就会在下次改档时漏掉，已经发生过一轮。
`scripts/check_docs.py` 会扫这条。

### 每档的可粘贴文本

选中档位后，把对应那段原样贴进视频提示词的尾部。**模板不复制这些文本，只指向这里。**

余量 ≤ 1.0s：

```text
保持完全静止直到片尾。
```

1.0s < 余量 ≤ 2.0s：

```text
【收束动作】，之后最后 0.6 秒保持完全静止。
```

余量 > 2.0s：

```text
随后保持完全静止【余量 − 1.0】秒，画面不得漂移，机位不得移动。
【收束动作】，之后最后 0.6 秒保持完全静止。
```

补差 ≤ 0.5s：

```text
到【关键动作截止】秒时，所有关键动作已经完成，每个元素都已到达最终位置。
最后 0.2 秒保持完全静止：不漂移、无呼吸式明暗、机位不动——
这一帧会在剪辑里被定格延长。
```

补差 > 0.5s：上面那段，再在末 0.2 秒之前加一次微动填充：

```text
在那之前的 0.2 秒，允许在**已经落位**的部件上做一次轻微的材质响应
（纸面下沉 2 像素、阴影略微加深）；不得引入新的主体。
```

展示型（入场结束后）：

```text
主体保持稳定。每一个字符固定不变。
【余量够大时加一次收束动作】
最后 0.2 秒：保持完全静止——这一帧会在剪辑里被定格延长。
```

拆分镜的上游片段（覆盖以上所有档）：

```text
从【生成时长−0.6】秒到片尾，精确停在桥接帧【B-ID】的排布上：
每个物体的位置、缩放、角度、阴影和可见文字全部固定，
不漂移、无呼吸式明暗、机位不动。
**最后这一帧会被截取出来，作为下一条片子的第一帧。**
```

【收束动作】从 [prompt-motion.md](prompt-motion.md) 第 3 节的动作库里取。

### 余量（生成 > 旁白）

余量 ≤ 1.0 秒纯定格，剪辑时裁掉或作转场重叠。
余量 > 1.0 秒先安排一次**收束动作**再定格——长时间纯静止会让模型自行发挥，
产生漂移和不稳定终帧。

**余量 > 2.0 秒时中段必须显式交代。** 收束动作加末段定格只占约 1.0 秒，
余量再大就会在关键动作与收束之间留出一段没人规定的时间——那正是模型自行发挥的入口。
写法是在关键动作与收束之间插一段明确的静止指令，
可粘贴文本取本节「每档的可粘贴文本」里「余量 > 2.0s」那一段，此处不重复。

这一档**只**出现在 `短镜`（自然时长 < 3.0 秒、生成 4 秒）——自然时长 ≥ 3 秒时
余量必然 ≤ 1.0（第 5 节的硬规律），不可能进这一档。
余量上限 3.2 秒，中段最多空出 2.2 秒——留白不写等于把这 2.2 秒交给模型即兴。

### 补差（生成 < 旁白）

关键动作全部压进生成时长内，**末帧必须稳定**——它要在剪辑里被定格延长。
补差 ≤ 0.5 秒直接末帧定格即可；**补差 > 0.5 秒**时不必全程冻死，
可在已入位的部件上加一次**微动填充**（纸张轻颤、阴影沉降）填住中段，末 0.2 秒再绝对稳定。

```text
到【关键动作截止】秒时，所有关键动作已经完成，每个元素都已到达最终位置。
最后 0.2 秒保持完全静止，不漂移、机位不动——这一帧会在剪辑里被定格延长。
在那之前的 0.2 秒，允许在已经落位的部件上做一次轻微的材质响应；不得引入新的主体。
```

**不要为了补差去新增飞入部件或展开新结构**——那会挤掉主动作并引入新知识点。
但微动填充（在已有部件上）是允许的，它填住中段又避免画面长时间完全卡住。

### 收束动作与微动填充是同一批动作的两种用途

**动作库是共用的**，含可直接粘贴的英文写法，正典在
[prompt-motion.md](prompt-motion.md) 第 3 节。本节不重复清单，以免副本少项。
两者的区别不在动作本身，只在触发条件与目的：

| | 收束动作 | 微动填充 |
|---|---|---|
| 触发 | 余量 > 1.0s | 补差 > 0.5s |
| 目的 | 填住片子比旁白长出来的尾巴 | 关键动作被压前完成后，避免画面长时间卡死 |

**所以「补差镜不写收束动作」的准确意思是：补差镜没有尾巴要填，不写那种用途的动作，
不是禁止一切材质响应。** 补差 > 0.5 秒时该写微动填充就写。

硬约束对两者同样成立：不引入新信息，也不构成第二个动作。
禁止写成再飞入一张卡片、再展开一层结构——那会让这一镜变成两个动作，违反第 3 节。
判据：动作里出现的物件，必须是本镜已在场、已入位的东西。

### 差值率

```
差值率 = 解释型镜头的 |差值| 合计 ÷ 解释型镜头的生成总时长
```

取绝对值，正负都算——补差同样是需要在剪辑里处理的偏差。

| 差值率 | 判断 | 处理 |
|---|---|---|
| ≤ 10% | 正常 | 直接进行 |
| 10–20% | 偏高 | 复查短镜是否有可并入的过渡句 |
| > 20% | 快节奏短句型内容 | 向用户提示，见下 |

就近吸附下，差值率超过 20% 的成因是 **4 秒档的镜太多**，短镜只是其中一类。
算术上：4 秒档单镜差值率上限是 1.0 ÷ 4 = **25%**，6 秒档 16.7%，8 秒档 12.5%，10 秒档 10%。
所以**一个短镜都没有**的片子照样能超 20%——三镜各自然 3.0 秒、各取 4 秒、余量各 1.0，
差值率就是 25%，而 3.0 秒按第 5 节属正常镜。
排查时先看 4 秒档镜数占比，不要只盯短镜。

差值率 > 20% 时给用户三个选项：

```
a. 接受。每镜写收束动作，成片自然带节奏停顿。（推荐）
b. 把并列型短镜（如「有的支持 A、有的支持 B、有的加 C」）合成一镜，
   用多部件分时入场消化——这正是多部件流规则的用武之地，无需特别标注。
c. 回到 SRT 层面，把过碎的字幕先合并再送入本 skill。
```

推荐 a：快节奏内容本来就需要停顿来消化。

## 7. 超限拆分与桥接帧

仅用于解释型镜头。自然时长 **> 11 秒**时：

```
1. 在本镜内部找出全部次级候选切点（动作完成点，不是时长中点）；
2. 对每个候选切点，算出它切出的 a、b 两段自然时长，各自按第 5 节就近取档；
3. 在**候选切点之间**比较，取 |(生成 a + 生成 b) − 本镜自然时长| 最小的那个切点；
   仍等值时取两段更均衡的那个；
4. 生成一个共享桥接帧：上游片段的末帧 = 下游片段的第 0 帧。
   默认走抽帧（截取上游成片的末帧作为下游的上传图），路线见
   [prompt-motion.md](prompt-motion.md) 第 6 节。
```

**超过 22 秒要递归拆。** 上面是二分，每段上限 11 秒，所以二分最多覆盖到 22 秒。
自然时长 > 22 秒时先二分，再对仍然 > 11 秒的那一段重复本节流程，直到每段都 ≤ 11 秒。
片段号顺延成 `S05a` / `S05b` / `S05c`……，每两段之间各有一个桥接帧。
此时规模公式第 9 节里的 Q 要按「该镜产出的片段数 − 1」计，不再是固定的 1。
展示型的多段分镜同理，见第 2 节的例外。

**a 和 b 由切点决定，不能自行挑组合。** 第 3 步比的是「哪个切点更好」，
不是「同一个切点下选 6+8 还是 4+10」——就近吸附下，切点定了时长就定了。
例如某镜 13.4 秒，切点落在 6.2 / 7.2 处，6.2 落在 (5,7] 取 6、7.2 落在 (7,9] 取 8，
只能得 6+8，不存在改成 4+10 的选项。
完整走法见 [../examples/end-to-end.md](../examples/end-to-end.md) 第六·五节。

**10–11 秒不拆。** 那一档取 10 秒生成，补差最多 1.0 秒，末帧定格补上即可。
为 0.2 秒的差去多出一条片子、一张桥接帧、一个接缝，成本完全不成比例。

拆分依据是**已完成的物理事件**，不是平均时长。

桥接帧必须逐像素一致的项：所有物体的位置、缩放、角度、阴影、可见文字、
调色板、光照方向、运镜落点。走抽帧路线时这一条自动成立，走单独出图路线时要逐项核对。

上游片段要求把桥接帧稳定保持至少 0.6 秒（否则抽出来的末帧是糊的），
下游片段要求从桥接帧开始、在第一个动作之前不改变布局。

## 8. 异常 SRT 处理

文件层的编码与脏格式见第 1 节「解析前清洗」，本节只管语义层。

| 情况 | 处理 |
|---|---|
| 单条字幕本身 > 11 秒 | 解释型进入第 7 节拆分，桥接帧在句中动作完成处；展示型不拆，取 10 秒 |
| 单条字幕 < 0.8 秒 | 一律并入相邻镜，不单独成镜 |
| **一条字幕横跨两个语义单元** | **不可在句中切分。判断哪一半是本镜的主语义，把整条归给它，另一半在下一镜的画面上以「已出现」状态承接。分镜表标注 `跨句`，提示剪辑时该镜尾部多留 2–3 帧** |
| 时间码重叠 | **把后一条的 start 推到前一条的 end**（不动前一条的 end，因为自然时长按 start 算，动 end 不影响结果、动 start 才影响）。标注 `待核实` |
| 时间轴有 > 3 秒的大段静默 | **仍并入前一镜**（第 1 节的时间归属规则没有例外），该镜自然时长因此变长，按吸附表正常取档；在分镜表标注 `长尾静默`，提示这一镜的后半段没有旁白、画面要自己撑住。不要单独成镜——静默段没有字幕，`字幕区间` 列填不了，自然时长也算不出来 |
| 缺序号或格式不标准 | 按时间码顺序重排，忽略序号 |
| 同一句被拆成多条（换行式字幕） | 先按语义合回完整句，再进入第一步 |

「跨句」的典型形态：`实验性。PageAI-Pro 的 ralph-loop，`——
前半句收尾上一个话题，后半句开启下一个。切点只能落在字幕边界上，
无论怎么切都会劈开一个语义单元，因此只能整条归属，靠画面承接。

## 9. 规模提示

分镜完成后、进入模式 3 之前，**必须先给出规模提示**。
本节是规模口径的唯一正典，其余文件引用本节、不重复公式。

记 `P` = 非拆分镜数，`Q` = 拆分镜数，总镜数 `N = P + Q`：

| 项 | 值 |
|---|---|
| 总镜数 | N（解释型 X / 展示型 Y，其中拆分 Q 镜） |
| 视频片段条数 | **P + 2Q** |
| 参考图张数 | **P + Q**（拆分镜走抽帧桥接，推荐）／ **P + 2Q**（片段 b 单独出图） |
| 预计生成调用 | 参考图张数 + 视频片段条数 |
| 批大小 | 见下 |
| 分批数 | ⌈N ÷ 批大小⌉ |

**三个数不可互相代入。** 一个拆分镜产出**两条片子**（a、b），所以片段条数是 P + 2Q 而不是 N。
参考图张数取决于桥接路线：

```
抽帧（推荐）：参考图 = P + Q = 总镜数 N，片段条数比它多 Q
出图（兜底）：参考图 = P + 2Q = 片段条数，两者都比总镜数多 Q
```

所以**总有两个数相等、第三个不同**，具体哪两个相等取决于路线。
不要凭「它们应该都等于总镜数」去套——Q > 0 时至少有一个数比 N 大。

**参考图角色与桥接帧路线的正典在
[prompt-motion.md](prompt-motion.md) 第 6 节**，上表按默认的抽帧路线计（参考图 = P + Q）。

批大小随规模调整（按总镜数 N，不按片段条数）：

| 总镜数 | 批大小 |
|---|---:|
| ≤ 30 | 5 |
| 31–40 | 8 |
| > 40 | 10 |

批大小取定值，`分批数 = ⌈N ÷ 批大小⌉` 才有唯一解。
用户要求一批少出几镜时可以下调，但要同时重算分批数。

总镜数 > 40 时，额外给出三个选项：

```
a. 全片出完；
b. 先出前两段验证风格与流程，确认后再出其余；（推荐）
c. 只交付分镜表与视觉圣经，提示词按镜号随用随取。
```

推荐 b：用不到十次生成验证方向，而不是先付出上百次的成本。

## 10. 分镜表格式

| 镜号 | 型 | 字幕区间 | 时间码 | 字幕 | 自然时长 | 生成时长 | 差值 | 视觉任务 | 知识点 | 主体/数量 | 主动作 | 构图 | 精确关键词 | 文字路线 | 转场锚点 | 标记 |
|---|---|---|---|---|---:|---:|---:|---|---|---|---|---|---|---|---|---|

- `型`：解释 / 展示
- `视觉任务` 只允许填五个值之一：`提问 question` / `机制 mechanism` /
  `证据 evidence` / `变化 change` / `结论 conclusion`。定义见
  [prompt-templates.md](prompt-templates.md) 第 1 节
- **`知识点`：一句话写清这一镜要让观众明白什么**，写的是语义不是画面。
  旁白是比喻时尤其要写——「被逼到了悬崖边」这类句子，字面照画会得到一道真悬崖。
  **一镜只能有一个**：需要用「并且」「同时」才描述得完，那就是两个知识点，
  回第 4 节的分镜算法重切，不要在提示词层面打补丁。
  这一列是三级优先级里第一条硬约束（语义完整）的**唯一书面记录**，
  也是参考图提示词「本镜知识点」字段的来源——不填，那条硬约束就落不到任何纸面上。
- `字幕区间`：本镜合并了哪几条 SRT，如 `3–5`
- `生成时长`：解释型直接填 4 / 6 / 8 / 10；展示型填 `展示 N.Ns → 生成 Ms`
  （箭头右侧仍是 4/6/8/10，自然时长超 10 秒时固定 10）。两种写法脚本都认，见下面的机器可读约束
- `差值` = 生成 − 自然，**带正负号**：正写 `余量 X.Xs`，负写 `补差 X.Xs`
- `文字路线` ∈ `generated` / `blank carrier + overlay` / `post only`
- `标记`，可叠加多个，用 `｜` 分隔：
  - `短镜` —— 自然时长 < 3.0 秒
  - `反组` —— 本镜取 `motion_dir: disassemble`，参考图画的是完整成品、并画出可拆分界，
    定义与编排上限见 [prompt-motion.md](prompt-motion.md) 第 6 节
  - `动感:A` / `动感:C` —— 展示型镜头选的动感预算档，**默认 B 不标**，只标偏离默认的那两档。
    取档规则见 [prompt-templates.md](prompt-templates.md) 第 5 节
  - `跨句` —— 一条字幕横跨两个语义单元，整条归属本镜
  - `拆分：S05a 6s → B → S05b 8s` —— 片段号与 `02_参考图/S05a_reference.png`、
    `03_生成视频/S05b_clip.mp4` 一致，档位一眼可见
  - `风格切换→S09：理由` —— 混合风格时必填，规则见
    [style-selector.md](style-selector.md) 第 6 节
  - `待核实` —— 时间码重叠等需要用户确认的项

表末给出汇总：总镜数、解释型与展示型各多少、SRT 总时长、生成总时长、
余量合计、补差合计、差值率、拆分镜数、短镜数、规模提示表。

### 机器可读约束

`scripts/check_storyboard.py` 要解析这张表，所以格式不能随手改：

- 标准 markdown 管道表，表头行与分隔行齐全，每行列数一致；
- `镜号` 形如 `S01`、`S05a`、`S05b`；
- `自然时长` / `生成时长` 只写数字，不带 `s` 以外的字符（展示型写 `展示 13.5s → 生成 10s` 时，
  脚本取箭头两侧的数字）；
- `差值` 固定 `余量 X.Xs` / `补差 X.Xs` / `0`，不写别的措辞；
- `型` 只填 `解释` 或 `展示`；
- `视觉任务` 填中英对照的五个值之一，脚本按英文部分匹配；
- `知识点` 一句话、非空，且不出现**并且／同时／以及／而且**这四个并列连词——
  这四个词是脚本的判定清单（`check_storyboard` 4d 与 `check_prompts` R1b 共用），
  别处引用本清单，不要各写各的；
- `字幕区间` 用半角或全角连字符都行，脚本两种都认。

表末汇总行用 `合计：` 开头，脚本据此判断表格结束。

## 11. 校验器

分镜表交付前逐条硬检查。任何一项失败，回到第二步重切。

**有 Python 就先跑脚本，把算术类的那几条一次性判掉：**

```bash
python scripts/check_storyboard.py <项目目录>/storyboard.md <字幕>.srt
```

脚本只读、不改文件，覆盖 1、2、3、4b、4c、4d、5、7、7b、9、11 这几条，外加一条编号 0 的
「表格可解析」——那一条不在下面的清单里，是脚本自己的前置检查。
输出里第 4 条拆成 4c / 4d，第 5 条拆成 5a–5d，所以脚本会打印 16 行。
其中 **7b 逐字比对旁白与上屏文字**是人工最容易放水的一条，交给机器最划算。
第三个参数可传文字密度（默认 `standard`）。

没有 Python 就按下面逐条人工过——脚本是可选加速，不是前置条件。

**机器只判「填得合不合法」，判不了「填得对不对」。** 以 4b 为例：
脚本能确认视觉任务是五个合法值之一，但那一镜该不该选「证据」，只有人能判。
因此第 6、8、10、12 全部要人工过；第 4 条的**并列连词形态**已由 4c/4d 初筛，
但「这一镜到底该讲哪个知识点、写得对不对」仍要人工过，4b 的选型是否恰当同理。

```
1. 每镜已标注解释型或展示型
2. 每镜的生成时长 ∈ {4, 6, 8, 10}，两型通用
3. 镜头区间首尾相接，无空洞、无重叠，完整覆盖 SRT 时间轴
4. 每镜 知识点数 == 1（一镜只讲一个知识点；但允许该知识点内多个部件分时间码
   依次入场，构成一个连续动作流。例如主体落下 → 辅助卡滑入 → 标题锁定，算一个知识点，
   不是三个）
4b. 每镜的视觉任务是五类之一，且同一镜只承担一类；
    连续三镜同类时已复查过是否该合并或改写
5. 差值 = 生成时长 − 自然时长，且**自然时长 ≥ 3 秒的镜头 |差值| ≤ 1.0**
   例外一：`短镜`（自然时长 < 3.0 秒且语义不允许合并）余量可达 3.2，
           尾部按第 6 节选档，并在分镜表标注 `短镜`
   例外二：展示型自然时长 **> 11 秒**时补差可超 1.0，属平台上限，不算失败。
           注意门槛是 11 不是 10——自然时长 ∈ (10, 11] 时按吸附表取 10，补差最多 1.0，
           本来就不需要豁免
6. 尾部按第 6 节的**尾部契约表**选档并落实。**本条不复述档位与数值**——
   查三件事：档选对了、末段绝对静止时长与该档一致、
   关键动作截止 == min(自然时长, 生成时长 − 该档需留)。
   拆分镜的上游片段被最后一行覆盖，一律 0.6 秒
7. 展示型镜头未被拆分，生成时长取的是最接近档（超 10 秒取 10）
7b. **展示型镜头的上屏文字完整覆盖本镜旁白**，无压缩、无删减。
    逐字比对：去标点、统一大小写后，旁白必须是本镜上屏文字的子序列。
    两处豁免：`跨句` 镜的越界半句（该半句由相邻镜的画面承接）；
    `文字路线` 为 `post only` 的镜（文字整体走后期叠加，参考图里本就不出现，
    改为核对后期文字清单是否完整覆盖旁白）。
    超 14 字块的行必须拆成多张卡，不得砍字——这一条失败时回到第二步重切，不要改文案
8. 标记为拆分的镜头，必须有桥接帧 ID，且上游片段的末帧 ID == 下游片段的第 0 帧 ID；
   已注明该帧怎么拿到（默认抽帧，兜底出图）
9a. **解释型**每镜文字数 ≤ `state.json` 里 `text_density` 对应的上限：
    `minimal` 2 / `standard` 5 / `editorial-dense` 8
9b. **展示型**每镜 ≤ 8 张卡、每张 ≤ 14 字块，**与文字密度档无关**——
    那 8 是版面可读性天花板，不是编辑密度选择。装不下时按第 2 节的例外
    分成两个展示镜，**不得砍字**。拆到 6–8 张时按语义分 2–3 组、每组一种载体形状
10. 每镜都有转场锚点，且与相邻镜可衔接
11. 已计算差值率，超 20% 时已向用户提示
12. 已给出规模提示表
```

第 4 条无法自动判定时，逐镜自问：这一镜能不能用一句话说清它在讲什么？
需要用「并且」「同时」才能说清，就是两个知识点，必须拆。
