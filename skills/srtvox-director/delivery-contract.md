# 输出契约（第 3 步定案）

完整提示词包的固定结构，共 10 段。窄需求可省略部分段落，但不得改变段序与字段名。

不设「旁白」段——旁白由 SRT 给定，本 skill 不写内容。
「风格试片」降为可选，并入 [style-gallery.md](style-gallery.md)「选定之后」一节。
「分批状态」是本 skill 独有的，因为 SRT 常带来几十镜的规模。

## 文件为准，对话只回摘要

几十镜的提示词全贴进对话，既没法用又烧上下文。**正文一律写文件，对话只回摘要。**

每批的对话输出固定这四块，不多不少：

```
1. 本批镜号一览——每镜一行：镜号 / 型 / 生成时长 / 视觉任务 / 一句话主动作
2. 本批写了哪些文件（带路径）
3. 进度块（见第 10 节）
4. 「回复继续出下一批」
```

**三种情况直接贴全文、不写文件**：模式 4 只补一镜、用户明说「直接贴给我」、
没有可写目录。

### 文件粒度

一镜一文件，参考图提示词与视频提示词放在同一个文件里：

```
01_提示词/00_视觉圣经.md
01_提示词/S01.md            镜 01 的参考图提示词 + 视频提示词
01_提示词/S05a.md           拆分镜按片段分
01_提示词/S05b.md
01_提示词/98_剪辑与后期.md
```

与 `02_参考图/S01_reference.png`、`03_生成视频/S01_clip.mp4` 是同一套镜号，
用户按镜号一条龙找完。分批只影响**什么时候写**，不影响文件怎么分。

### 输出目录

**默认就是 SRT 文件所在的那个目录**，不另建子目录——用户把字幕放哪，产出就落在哪。
只有用户明确指定别的路径时才改。目录写进 `state.json` 的 `output_dir`，
并在项目简报里把绝对路径写出来，让用户知道文件会出现在哪。

## 1. 项目简报

- SRT 文件名与路径、**编码**（读出来乱码就换编码重读，探测顺序见
  [storyboard-algorithm.md](storyboard-algorithm.md) 第 1 节；定下来写进 `state.json` 的 `srt_encoding`）
- 字幕条数、SRT 总时长
- 镜头数（解释型 / 展示型各多少）、生成总时长、**余量合计、补差合计、差值率**
- 画幅、目标平台、单片时长上限（默认 4/6/8/10 秒，`待核实`）
- **参考图角色**：上传图是垫图/视觉依据，模型重新生成第 0 帧并演化到终态，
  参考图画的是这一镜的目标构图。定义见 [prompt-motion.md](prompt-motion.md) 第 6 节
- 风格模式：选定 / 推荐 / 自定义 / 混合
- 文字密度：minimal / standard / editorial-dense
- **是否新手**（决定要不要附 [delivery-handoff.md](delivery-handoff.md) 的小白操作卡，写进 `state.json` 的 `beginner`）
- 假设与 `待核实` 项

**规模提示**（分镜完成后必给，进入模式 3 之前）。

**口径与公式只有一处正典：[storyboard-algorithm.md](storyboard-algorithm.md) 第 9 节**——
包括参考图张数、片段条数、批大小、分批数、以及总镜数 > 40 时必给的三个选项。
本契约不复述公式，只规定它出现在项目简报段的末尾。

特别注意那一节的告诫：**三个数不可互相代入**。走抽帧路线时参考图张数恰好等于总镜数、
片段条数比它多；走出图路线时参考图张数等于片段条数、两者都比总镜数多。
总有两个数相等，但相等的是哪两个取决于桥接路线，别凭直觉套。

不写旁白正文——旁白由 SRT 给定，只给统计。

## 2. 风格决策

用户未选风格时，给三个实质不同的方向：

| 方向 | 解释世界 | 最适用 | 关键词载体 | 运动签名 | 取舍 |
|---|---|---|---|---|---|

三者必须在**解释世界与运动逻辑**上不同，不能只换配色。

已选风格则跳过对比，给一句选型理由。

无论哪种，都要给选中方向的**完整风格 DNA**——字段清单与顺序以
[style-selector.md](style-selector.md) 第 4 节为准，本契约不复述字段名。

自定义风格：从用户参考图提取可复用设计原则，并显式声明不可复制项
（logo、构图、具名艺术家、可识别角色）。

## 3. 视觉圣经

**字段清单以 [prompt-templates.md](prompt-templates.md) 第 2 节的可粘贴模板为唯一正典**，
本节不复述字段定义，只列交付时要逐项确认「锁死」的那些参数——它们是模板里
要求全片统一的项，交付前要确认每一项都已定值且不再随镜变化。下面每一条的精确取值
（例如字幕安全区的像素数）仍查模板，不在这里复述：

跨全片锁死的参数（每项的定义见模板第 2 节）：

- 画幅、分辨率、字幕安全区（像素取值查模板第 2 节）
- 运镜家族与焦段感
- 主体大小、角度、位置、**精确数量**
- **前景 / 中景 / 背景三层规则**：三层各放什么、清晰度与明度关系、
  哪层承载主信息、哪层只做环境。全片统一，不得逐镜变化
- 材质系统与纹理
- 3–5 个颜色**及其角色**
- 光照方向与阴影柔硬度
- 关键词载体类型、字体层级、标题固定区
- 转场锚点
- 人物 / 地图 / 图表 / 数字的统一处理
- 运动物理与声音质感
- 禁止视觉漂移（具体的失败形态，例如该风格容易滑向哪些邻近风格）

## 4. 分镜与关键词台账

**分镜表的列定义只有一处正典：[storyboard-algorithm.md](storyboard-algorithm.md) 第 10 节。
本契约不重复表头、也不写列数，以免两份定义各自漂移。** 交付时按那一节的列序原样输出，
并附上该节要求的表末汇总（总镜数、两型各多少、SRT 总时长、生成总时长、
余量合计、补差合计、差值率、拆分镜数、短镜数、规模提示表）。

本段只补充输出契约层面的额外要求：

- 关键词台账与分镜表**同段交付**，台账在表之后，按镜号排列，模板见
  [prompt-templates.md](prompt-templates.md) 第 3 节；
- 台账里的每个上屏文字必须在分镜表的 `精确关键词` 列里出现过，两处逐字一致；
- `文字路线` 三个取值的判定条件见 [prompt-keywords.md](prompt-keywords.md)「渲染路线决策」，
  本契约不复述字数范围。默认走 `generated`，`blank carrier + overlay` 是兜底不是默认。

## 5. 参考图提示词

每张一节：

### 图 N — 描述性文件名

- 用于：镜号 / 片段号（拆分镜写 `S05a`、`S05b`）
- 角色：`目标构图`（常规）/ `桥接帧`（拆分镜片段 b 的首帧）
- **随附风格板**：本片风格板的绝对路径，写在这一节最前面，让用户不必回头翻。
  全片每一镜都是同一张，路径由 `state.json` 的 `style_id` 拼出来，
  拼法见 [style-gallery.md](style-gallery.md)「风格板」一节
- 画幅、精确主体数量
- **本镜旁白原文**（逐字照抄 SRT 的 `raw_text`，写进提示词给模型语境）
- **视觉任务**：五类之一
- **目标构图**：各部件的排布与状态（哪些已就位、哪些还处于未落位状态）
- **前景 / 中景 / 背景**三层各放什么
- 上屏文字包：精确文字、载体、层级、位置、渲染路线
- 完整提示词（中文，含完整硬性约束，模板见 [prompt-templates.md](prompt-templates.md) 第 4 节）
- 空白载体兜底版（关键文字时提供）
- 精简的、针对本主体的负面提示

## 6. 视频提示词计划

先给总表：

| 片段 | 型 | 生成时长 | 上传图 | 终态 | 主动作 | 文字卡动作 | 运镜 | 尾部处理 |
|---|---|---:|---|---|---|---|---|---|

`上传图` 填这条片子要上传哪张图（`S05a_reference.png` / `S05b_bridge.png`）；
`终态` 是文字描述，没有第二张图去钉它。

再逐条给提示词，每条含：

1. 画幅、时长、景别、运动强度
2. 参考图的角色
3. 开场状态
4. 带时间码的动作
5. 主体位移：起点、终点、距离、旋转、顺序、材质响应
6. 运镜轨迹
7. 文字卡作为完整物体运动（禁止逐字生成、改写、闪烁、变形）
8. **尾部处理**：按 [storyboard-algorithm.md](storyboard-algorithm.md) 第 6 节的
   **尾部契约表**选档，动作从 [prompt-motion.md](prompt-motion.md) 第 3 节的动作库里取。
   本契约不复述档位名与数值
9. 精确终态与定格
10. 声音建议
11. 负面约束与验收标准

**桥接帧清单**（有拆分时必给）：

| 桥接帧 | 上游片段末帧 | 下游片段第 0 帧 | 怎么拿到（抽帧 / 出图） | 必须逐像素一致的项 |
|---|---|---|---|---|

## 7. 剪辑与后期

- **差值处理表**：每镜生成多少秒、旁白多少秒、差值正负、尾部是裁掉、收束还是定格延长
- 音画对齐：以 SRT 时间码为准
- 转场重叠：两到三帧，或用一次短促物理遮挡
- 后期文字清单：完整字幕、密集数据表、多位小数、品牌文案、引用来源
- 变速指引：全表见 [prompt-motion.md](prompt-motion.md) 第 7 节，本契约不复述
- 声音层：每镜保留一到两个重要材质音

不含配音生成——旁白已存在。

### 输出目录结构

本 skill 只写 `01_提示词/` 里的文本文件与 `state.json`，另外三个目录留给用户自己存放
在别的平台生成的媒体。**给用户的文件名必须带上这个目录前缀**，否则几十个文件会散在一处。

```
<SRT 所在目录>/
├── 校园招新.srt            你的输入，本 skill 只读不改
├── state.json              本 skill 写
├── storyboard.md           本 skill 写：分镜表 + 关键词台账
├── 01_提示词/              本 skill 写，一镜一文件
│   ├── 00_视觉圣经.md
│   ├── S01.md              参考图提示词 + 视频提示词
│   ├── S02.md
│   ├── S05a.md             拆分镜按片段分文件
│   ├── S05b.md
│   └── 98_剪辑与后期.md
├── 02_参考图/              用户存：SNN_reference.png
├── 03_生成视频/            用户存：SNN_clip.mp4
└── 04_成片/                用户存：剪辑导出
```

`SNN` 是镜号（`S01`、`S02`……），与分镜表的镜号一致。
**注意它与风格 ID（也写作 `S01`）同形不同义**，靠所在目录区分：
项目目录（`01_提示词/` `02_参考图/` `03_生成视频/`）里的 `SNN` 一律是**镜号**；
skill 包自带的 `assets/style-samples/S01-现代纸艺.jpg` 与 `state.json` 的 `style_id`
里的 `SNN` 才是**风格 ID**。两者永远不在同一个目录下出现，不会混。

拆分镜一镜两片，文件名带片段号：

```
02_参考图/S05a_reference.png     片段 a 的参考图（出图）
02_参考图/S05b_bridge.png        片段 b 的桥接帧（从 S05a_clip.mp4 抽末帧，不出图）
03_生成视频/S05a_clip.mp4
03_生成视频/S05b_clip.mp4
```

### 用户自检表

用户自己生成后，逐张逐条对照。任何一项不过，只重生成失败的那一张，不要整批重来。

**参考图八项**

| 项 | 检查什么 |
|---|---|
| 画幅 | 与分镜表一致，且与后续视频画幅一致 |
| 目标构图 | 参考图画的是本镜想呈现的核心画面，且是个成立的构图、不是待填底板：三层与转场锚点已完整，各部件排布与提示词「目标构图」那行的描述一致。**标 `反组` 的镜**：参考图本就是完整成品，这一项改查接缝、转轴、分层线有没有画进图里（见 prompt-motion 第 6 节） |
| 主体数量 | 与提示词写的「精确主体数量」完全相同，没有多出的重复主体 |
| 文字 | 本镜文字包里的每个关键词都已印在载体上、逐字正确、清晰可读；未列入文字包的表面全部留空 |
| 连续性 | 与相邻镜的转场锚点位置、尺寸、颜色、方向一致 |
| 漂移 | 材质、调色板、光照方向没有偏离视觉圣经，没有滑向邻近风格。**同时查风格板有没有漏进画面**：出现分区格子、标签条、并排的方形样本，就是版式被当成构图抄了，补回「随附的风格板」那三行重出 |
| 无运动模糊 | 画面里没有任何拖影，否则视频模型会把模糊当材质，整片糊掉 |
| 形状完整 | 物体没有残缺边缘或断裂轮廓，否则动画时会扭曲、融化、闪烁 |

末两项是图生视频专用，静态图看着没问题也要查。

**视频片段六项**

| 项 | 检查什么 |
|---|---|
| 开场状态 | 生成片的第 0 帧不必与上传图逐像素一致（上传图是垫图，模型会重新生成），但开场时各部件的位置要符合视频提示词「开场状态」的描述 |
| 位移 | 至少三个主要部件有可见物理位移，不是只有光效 |
| 文字 | 载体整块移动，字符没有被逐字重绘、改写、闪烁；没有凭空长出新的字 |
| 终帧 | 终态与视频提示词描述的一致；末段绝对静止的长度符合该镜在**尾部契约表**里的那一档（[storyboard-algorithm.md](storyboard-algorithm.md) 第 6 节） |
| 数量 | 全程物体数量没有增减 |
| 桥接 | 拆分镜片段 b 的第 0 帧＝片段 a 的末帧（抽帧时自动成立，单独出图时逐项核对） |

展示型镜头额外检查：入场时间按 storyboard-algorithm 第 2 节的公式算（本文件不复述），
入场后**带字载体**保持稳定；
尾部是否加收束动作、末段静止多久，按尾部契约表的「展示型」那一档核对。
不得用呼吸亮度或背景平移**代替**带字载体的入场位移——禁的是拿它顶替入场，
不是禁止它出现：B / C 档里读字保护区外的无字装饰动作是允许的，
取档见 prompt-templates 第 5 节。

## 10. 分批状态

每批输出末尾固定给这一块：

```
本批：镜 05–08（共 4 镜）
下批：镜 09–12
进度：8 / 18 镜
状态文件：<项目目录>/state.json
```

结尾固定一句：回复「继续」出下一批。

### state.json

写在输出目录根部，每批结束时更新。**这是断点续跑的唯一状态源。**

```json
{
  "project": "项目名",
  "srt_path": "字幕文件绝对路径",
  "srt_encoding": "gbk",
  "output_dir": "输出目录绝对路径",
  "storyboard_path": "storyboard.md",

  "style_id": "S01",
  "style_locked": true,
  "aspect": "16:9",
  "text_density": "standard",
  "beginner": true,
  "clip_limits": [4, 6, 8, 10],
  "platform": { "image": "ChatGPT Images", "video": "Google Flow", "edit": "剪映" },

  "total_shots": 18,
  "shot_types": { "explain": 15, "display": 3 },
  "split_shots": [5, 12],
  "bridge_frames": [
    { "shot": 5, "id": "S05b", "source": "extract" },
    { "shot": 12, "id": "S12b", "source": "extract" }
  ],
  "scale": { "reference_images": 18, "clips": 20, "calls": 38 },
  "delta_rate": 0.071,

  "batch_size": 5,
  "shots_done": [1, 2, 3, 4],
  "next_batch": [5, 6, 7, 8],
  "open_issues": []
}
```

**JSON 键固定用英文，显示值用中文。** 下面两个字段的键名与正文里出现的中文对应关系，
续跑时不要混填：

| 字段 | JSON 键（英文） | 对应中文（分镜表与正文） |
|---|---|---|
| `shot_types` | `explain` / `display` | 解释 / 展示 |
| `bridge_frames[].source` | `extract` / `render` | 抽帧 / 出图 |

`text_density` 取值本身就是英文标识符（`minimal` / `standard` / `editorial-dense`），
分镜表里不会出现它的中文，不存在这一层映射。

**边界原则：`state.json` 只存决策与进度，不存内容。** 逐镜的时长、差值、文字包、
提示词正文一律在 `storyboard.md` 和 `01_提示词/` 里，这里不复制——
否则这个文件会长成第二份分镜表，然后和真正的分镜表各自漂移。

判据：一个字段该不该进来，看**续跑时重推它会不会错**。
`text_density` 重推错一档，后面所有镜的文字数跟着错，所以要存；
第 3 镜的差值是多少，`storyboard.md` 里写着，重读即可，不存。

### 续跑

用户回来时先读 `state.json`，不要重新分镜、不要重新选风格。

**读完先校验**：`total_shots` 与 `storyboard.md` 的实际行数是否一致。
对不上说明用户手动改过分镜表，**停下来问**，不要闷头往下出提示词——
按旧状态出的提示词镜号会全部错位。
有 Python 就先跑 `python scripts/check_state.py <项目目录>`，它一次性三向对账
（state ↔ storyboard ↔ 提示词）、style_id 一致、batch_size 与分档表、scale 自洽，
比手数行数可靠。schema 仍以本节为准，脚本只判不写。

`style_locked` 为 true 时，任何模式都不得更换风格，除非用户显式要求。

`batch_size` 由总镜数决定，分档表见 [storyboard-algorithm.md](storyboard-algorithm.md) 第 9 节。
全片统一把上传图当垫图、模型重新生成第 0 帧，参考图与视频提示词都按这个口径写。

**`motion_dir` 不进这个文件。** 它是逐镜的决定，落在 `storyboard.md` 的 `标记` 列（`反组`），
续跑时重读分镜表就有，按上面的边界原则不该在这里存第二份。
展示型的动感预算档同理，落在同一列（`动感:A` / `动感:C`，默认 B 不标），
两个标记的取值定义都在 [storyboard-algorithm.md](storyboard-algorithm.md) 第 10 节。

`text_density` 决定**解释型**每镜的文字上限（三档取值查 prompt-keywords「三档密度」，
本文件不复述），校验器第 9a 条直接查它，所以必须落盘——
续跑时重推错一档，后面所有镜的文字数都跟着错。展示型不查这个字段，见 9b。
