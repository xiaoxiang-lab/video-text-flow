## 2026-08-15 首次实战（试点验证，宇树 IPO 项目）

### A. 环境与连接

- [A1] **MCP 配置后必须重启 opencode**：opencode.jsonc 里的 mcp 配置只在启动时加载，会话中途写入不生效（本次踩坑：配置写好但当前会话无 chrome-devtools 工具，重启后才可用）。
- [A2] **工作区根目录决定 upload_file 路径权限**：upload_file 只能传 opencode 工作区根（cwd）内的文件。本次踩坑：参考图在 Desktop\test\，opencode 工作区是 Default Project，被拒两次（"not within any of the configured workspace roots"）→ 解法：先把文件复制进工作区内再上传。
- [A3] **页面 uid 频繁重渲染失效**：Flow 页面动态渲染，a11y uid 会变（"Node is detached" / "no longer exists"）。每次操作前重新 take_snapshot 拿最新 uid；元素交互失败先重取快照。

### B. 提示词输入（关键，本次最大坑）

- [B1] **⚠ type_text 输入多行文本 = 灾难**：type_text 输入含换行的长提示词时，每个换行符被当作 Enter 提交，Flow 把每段**独立触发生成**（智能体/即时提交模式）→ 媒体列表出现一堆内容残缺的失败项（"背景是纯白底"、"镜头："、"shot-001.png简动态舞台…"单独成项），且**消耗点数**。绝对禁止用 type_text 输入多行提示词。
- [B2] **✅ 正确输入方式：剪贴板粘贴**：① PowerShell `Set-Clipboard -Value <提示词>`（单段无空行精简版）② 点击输入框聚焦 ③ Ctrl+V 粘贴。纯文本整体贴入，不触发提交，内容完整（350 字验证通过）。Flow 输入框是 Slate contenteditable，粘贴会保留为单个文本块。
- [B3] **参考图引用 = 输入框内 @ 触发**：在提示词开头输入 `@` → 弹出媒体选择对话框 → 点图片 → 点「添加到提示」→ 引用插入光标位置（显示为 "shot-001.png" 节点）。不要在「起始」帧位纠结拖拽——**@引用就是 image2video 的参考图机制**（起始/结束帧位是另一套首尾帧功能，拖拽交互与 MCP 不兼容）。
- [B4] **提示词建议精简为单段**：handoff 的多段结构（风格块/镜头/避免 + 空行）粘贴会带换行，虽粘贴不触发提交但建议合并为一段（逗号/句号分隔），降低输入复杂度。
- [B5] **输入完成后验证**：用 evaluate_script 读 contenteditable 的 innerText，确认长度与剪贴板一致、无截断、无意外提交。

### C. 页面结构与操作

- [C1] **编辑页 vs 项目页**：项目页 URL `.../project/<id>` = 创建界面（起始/结束/输入框/创建按钮）；`.../edit/<id>` = 媒体编辑页（图片编辑 Nano Banana / 视频编辑 Omni Flash + 时间轴）。点媒体库项会导航到 edit 页，点「返回项目」回创建页。
- [C2] **模型/时长/画幅选择**：点输入框上方按钮（如 "视频 · 6s crop_16_9 x2"）展开菜单：类型 tab（图片/视频）、模式 tab（帧/素材）、画幅（16:9 等）、模型（Omni Flash）、时长档（4/6/8/10s）、清晰度（x1-x4）。切 6s 后点数显示变化（24→20，6s 档 4 点数/次）。
- [C3] **Cookie 条/横幅是常态**：页面会弹 Google Cookie 同意条（glue-cookie-notification-bar，Agree 按钮）和活动横幅（Daily Bonus / avatar 推广 / Omni Flash 上新），正常关闭即可，不是安全事件。
- [C4] **点数耗尽提示**："您的 Google Flow 点数已用尽"——测试账号每日 50 点（每天刷新），生成前先确认点数足够，失败重试也可能耗点。

### D. 失败项与清理

- [D1] 媒体列表里失败的生成项带 "warning 失败 糟糕，出了点问题！" + 按钮（重试/重复使用提示/删除）。用「删除」清理错误项，不影响媒体库里的参考图。
- [D2] 错误的生成视频项（内容不是提示词内容）= 输入方式错误的分段提交产物，直接删除，不要「重试」（重试会再耗点数且重复错误内容）。

## 2026-08-17 档位实测（宇树 IPO 5 镜，第 0 轮统计）

- [E1] **Flow 实际成片时长 ≈ 档位整秒（实测 4 档 4.01s / 6 档 6.02s / 8 档 8.00s）**：5 镜
  全部余量（实测 − 旁白 > 0），差值 0.26 / 0.65 / 0.48 / 0.33 / 0.90s，无补差。
- [E2] **D1 的 7.23s（8s 档）是孤例**：2026-08-11 首期项目出现一次，其后两期（2026-08-15 试点 +
  2026-08-17 全量 5 镜）4/6/8 档全部整秒。未再复现，归因可疑（当时 350 字多行分段提交事故同批），
  继续按整秒假设，但每期仍由 merge-video 自动记录（.work/flow-duration-log.json）防复发。
- [E3] **差值算术前提成立**：差值 = 档位 − 旁白（实测误差 <0.1s 可忽略），就近吸附规则可落地。

## 2026-08-17 垫图认知（第 1 轮）

- [F1] **上传参考图 = 垫图/目标构图，不是第 0 帧**：图生视频时上传的参考图是「垫图」，
  模型会**重新生成第 0 帧**并从它演化到目标构图。因此生成片第 0 帧 ≠ 上传图，这是正常的
  （用户曾困惑「生成内容不是提示词内容」，部分就是垫图机制）。验收第 0 帧按
  「开场状态符合提示词」看，不按「与上传图逐像素一致」看（docs/review-checklist.md 视频六项-1）。
- [F2] **提示词尾部按差值写**：余量镜（视频长于旁白）尾部写静止/收束，裁尾对齐；**补差镜**
  （视频短于旁白，merge-video 会警告）尾部必须写「末帧绝对稳定、将被定格延长」——
  裁尾对补差镜无效（-t 不能拉长），只能靠末帧定格补足或重新生成更长档。

## 2026-08-17 桥接帧（第 4 轮）

- [G1] **拆分镜桥接 = 抽帧**：解释型自然时长 >11s 拆成 a/b 两段后，片段 a 的末帧截出来作为
  片段 b 的第 0 帧上传（`S05a_clip.mp4` 末帧截图 → `S05b_bridge.png` → Flow 图生视频首帧）。
  抽帧要求上游末段稳定保持 ≥0.6s（提示词里写「最后 0.6 秒精确停在桥接帧排布上」），
  否则抽出来的末帧是糊的。
- [G2] 检查拆分镜是否成对（check_jobcard「拆分不成对」）：有 a 必有 b，桥接 ID 一致。
  10-11s 不拆（取 10 档补差 ≤1.0s，末帧定格即可，为 0.2s 的差多出一条片子不值）。
